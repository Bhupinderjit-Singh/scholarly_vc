# Project Structure and Conventions

Scholarly is a small monorepo: a Next.js web app, a Python analysis worker, documentation, and the Kiro steering and specs. Vercel deploys `web/` (project root directory set to `web/`); Modal deploys `worker/`.

## Where things go

- **Business rules** (what counts as study time, when a session is joinable, how a streak is computed, how caps are checked, how a report is derived) are pure functions in `web/lib/domain` or `worker/pipeline/metrics.py`, each with unit tests. Route handlers, server actions, and Modal functions call them; they do not contain the rules themselves.
- **Authorization** is a guard function in `web/lib/auth` (`requireUser`, `requireHost(sessionId)`, `requireParticipant(sessionId)`, `requireAdmin`) called at the top of every handler.
- **Database schema** is a single Drizzle schema module per area under `web/lib/db/schema/` (`auth.ts`, `sessions.ts`, `tracking.ts`, `notifications.ts`, `calendar.ts`, `analysis.ts`), re-exported from `web/lib/db/schema/index.ts`.
- **Notifications** are created through one function (`notify(userId, type, payload)`) that writes the in-app row and fans out to email and push according to preferences. Features never call Resend or web-push directly.
- **Scheduled work** is a list of idempotent jobs in `web/lib/scheduler/jobs/*.ts`, all executed by `POST /api/cron/dispatch`.

## Naming

- Files and folders: kebab-case (`session-card.tsx`, `study-time.ts`). React components: PascalCase exports. Functions and variables: camelCase. Database tables and columns: snake_case. Python modules and functions: snake_case.
- Requirement IDs `F<spec>-R<n>` (for example `F2-R7`) are referenced in test names (`describe("F2-R7 token issuance")`), in commit bodies, and in Kiro task descriptions so every change traces back to a requirement.
- Environment variables: UPPER_SNAKE_CASE; browser-visible ones start with `NEXT_PUBLIC_`.
- LiveKit room names: `session-<sessionId>`. R2 keys: `recordings/<userId>/<sessionId>/<recordingId>.<ext>`.

## Git and delivery

- Single long-lived branch `main`. Feature branches are optional; squash before merging.
- Conventional Commits. Subject in imperative mood, capitalized, no trailing period, 50 characters or fewer; body explains what and why, wrapped at 72.
- Build and test before every commit. Never rewrite pushed history.
- Specs are implemented in order 01 → 06. Each spec's `tasks.md` (generated by Kiro) should end in a demoable increment.
